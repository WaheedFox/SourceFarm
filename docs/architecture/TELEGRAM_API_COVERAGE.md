# تغطية Telegram Bot API — SourceFarm وTitan

**مرجع الحقيقة:** [Telegram Bot API الرسمي](https://core.telegram.org/bots/api)، إصدار `10.3`؛ آخر تحديث ظاهر في صفحة المرجع 24 أغسطس 2026؛ تم جلب الصفحة وقراءتها في 7 نوفمبر 2026.  
**نطاق المصفوفة:** طرق API ومعاملاتها، جميع أنواع البيانات وحقولها، وجميع حقول Update في الإصدار المذكور. هذه مقارنة بين reference وبين Snapshot المستودعات العامة، وليست ادعاءً أن كل method جُرّب على Telegram.

## طريقة قراءة الحالات

- `SourceFarm = NOT IMPLEMENTED`: لا يوجد Builder أو Action Registry في SourceFarm يعرّض الطريقة/النموذج للمستخدم.
- `Titan = PARTIAL`: يوجد wrapper محدد، لكنه يمرر subset من المعاملات ولا يمثل schema كاملة.
- `Titan = RAW ONLY`: يوجد transport عام يقبل اسم method وJSON؛ هذا ليس Action typed، ولا يضمن عمل كل طريقة أو كل permission/context.
- `Optional` في قائمة الحقول يطابق وصف المرجع الرسمي حين يذكر صراحة أن الحقل اختياري. `*` في معاملات method يعني required بحسب جدول Telegram؛ `?` يعني optional.
- لا توجد metadata في SourceFarm/Titan تربط كل method بصلاحيات بوت Telegram أو صلاحيات العضو/القناة أو سياق المنتدى/الرسالة. لذلك هذا الجانب `غير ممثل/غير متحقق` لكل API method، لا استنتاجاً بأن الطريقة لا تحتاج صلاحيات.
- لا توجد اختبارات اتصال حية بـ Telegram أو تغطية شاملة لكل الطرق والحقول؛ اختبارات Titan تستخدم mocks/fixtures.

## منهجية الاستخراج وإعادة إنتاج الأعداد

جُمعت البيانات آلياً من HTML صفحة Bot API الرسمية التي تعرض `Bot API 10.3`، من دون API key أو ربط حساب. قرأ parser عناوين الفصول (`h3`)، والعناوين الفرعية (`h4`)، وكل صفوف الجداول التابعة لكل عنوان. صنّف headings ذات نمط lowerCamelCase كطرق ضمن فصول الطرق المحددة، وPascalCase كأنواع ضمن فصول الأنواع المحددة؛ ثم أخذ معاملات كل جدول `Parameter` وحقول كل جدول `Field`. `*` و`?` في المصفوفة مأخوذان من عمود required/optional أو وصف Optional في المرجع.

أُجريت فحوص اتساق على Snapshot نفسها: 185 اسم method فريداً بلا تكرارات، و400 اسم type فريد بلا تكرارات، ولا يوجد اسم parameter مكرر داخل method أو field مكرر داخل type. يفحص السكربت أيضاً عدم وجود headings بأسلوب method خارج فصول الطرق المحددة أو بأسلوب type خارج فصول الأنواع المحددة. توجد 177 جداول معاملات و932 صف معامل؛ 8 طرق بلا جدول معاملات. وجدت 365 جدول Field و1,888 صف حقل. يشمل Update عدد 28 حقلاً. كما يُنهى parser صراحةً بـ `close()` ثم يثبت أن آخر type في هذا الـ snapshot هو `GameHighScore`. هذه الفحوص تكشف تكراراً أو سقوطاً بنيوياً معروفاً، لكنها لا تثبت صحة معنى كل وصف في Telegram أو قبول الخادم لكل تركيبة.

**تصحيح مهم عن النسخة السابقة:** الأعداد `399 types / 364 field tables / 1,885 fields` كانت ناقصة؛ parser السابق لم ينهِ آخر heading في HTML. العنصر الذي سقط هو `GameHighScore` وله ثلاثة حقول. بعد إنهاء parser صراحةً بـ `close()` وإعادة جلب الصفحة ظهرت الأعداد الصحيحة هنا: `400 / 365 / 1,888`. أعداد الطرق `185` وحقول Update `28` لم تتغير.

يمكن إعادة إنتاج الجرد والفحوص باستخدام Python القياسي (لا يحتاج حزم خارجية) بهذا المقتطف؛ لا يرسل أي طلب إلى Bot API ولا يستدعي أي method:

```python
from collections import Counter
from html.parser import HTMLParser
from urllib.request import Request, urlopen
import re

URL = "https://core.telegram.org/bots/api"
request = Request(URL, headers={"User-Agent": "Mozilla/5.0"})
html = urlopen(request, timeout=30).read().decode("utf-8", "replace")

class Inventory(HTMLParser):
    def __init__(self):
        super().__init__(convert_charrefs=True)
        self.section, self.blocks = "", []
        self.h3 = self.h4 = False
        self.h3_text, self.current = [], None
        self.table = self.row = self.cell = None
    def finish_heading(self):
        if self.current:
            self.current["title"] = " ".join(self.current["title"].split())
            self.blocks.append(self.current)
            self.current = None
    def handle_starttag(self, tag, attrs):
        if tag == "h3":
            self.finish_heading(); self.h3 = True; self.h3_text = []
        elif tag == "h4":
            self.finish_heading(); self.h4 = True
            self.current = {"section": self.section, "title": "", "tables": []}
        elif self.current and tag == "table": self.table = []
        elif self.current and self.table is not None and tag == "tr": self.row = []
        elif self.current and self.table is not None and tag in ("td", "th"): self.cell = []
    def handle_data(self, data):
        if self.h3: self.h3_text.append(data)
        if self.current and self.h4: self.current["title"] += data
        if self.cell is not None: self.cell.append(data)
    def handle_endtag(self, tag):
        if tag in ("td", "th") and self.cell is not None and self.row is not None:
            self.row.append(" ".join(" ".join(self.cell).split())); self.cell = None
        elif tag == "tr" and self.row is not None and self.table is not None:
            self.table.append(self.row); self.row = None
        elif tag == "table" and self.table is not None and self.current:
            self.current["tables"].append(self.table); self.table = None
        elif tag == "h4": self.h4 = False
        elif tag == "h3":
            self.section = " ".join(" ".join(self.h3_text).split()); self.h3 = False
    def close(self):
        super().close()
        self.finish_heading()  # required: flush the final h4 at EOF

parser = Inventory()
parser.feed(html)
parser.close()
method_sections = {
    "Getting updates", "Available methods", "Updating messages", "Stickers",
    "Rich messages", "Inline mode", "Payments", "Telegram Passport", "Games",
}
type_sections = {
    "Available types", "Getting updates", "Stickers", "Rich messages",
    "Inline mode", "Payments", "Telegram Passport", "Games",
}
method_pattern = re.compile(r"[a-z][A-Za-z0-9]*")
type_pattern = re.compile(r"[A-Z][A-Za-z0-9]*")
methods = [b for b in parser.blocks if b["section"] in method_sections
           and method_pattern.fullmatch(b["title"])]
types = [b for b in parser.blocks if b["section"] in type_sections
         and type_pattern.fullmatch(b["title"])]
unclassified_methods = [b["title"] for b in parser.blocks
                        if method_pattern.fullmatch(b["title"])
                        and b["section"] not in method_sections]
unclassified_types = [b["title"] for b in parser.blocks
                      if type_pattern.fullmatch(b["title"])
                      and b["section"] not in type_sections]
def table(block, header):
    return next((t for t in block["tables"]
                 if t and t[0] and t[0][0].lower() == header.lower()), [])
parameter_tables = [table(b, "Parameter") for b in methods]
params = sum(len(t) - 1 for t in parameter_tables if t)
parameters = [(b["title"], row[0]) for b in methods
              for row in table(b, "Parameter")[1:] if row]
field_tables = [(b, table(b, "Field")) for b in types if table(b, "Field")]
fields = [(b["title"], row[0]) for b, t in field_tables for row in t[1:] if row]
updates = next(b for b in types if b["title"] == "Update")
assert len(methods) == len({b["title"] for b in methods}) == 185
assert len(types) == len({b["title"] for b in types}) == 400
assert len(field_tables) == 365 and len(fields) == 1888
assert sum(bool(t) for t in parameter_tables) == 177
assert sum(not t for t in parameter_tables) == 8 and params == 932
assert len(table(updates, "Field")) - 1 == 28
assert not unclassified_methods and not unclassified_types
assert not [(key, n) for key, n in Counter(parameters).items() if n > 1]
assert not [(key, n) for key, n in Counter(fields).items() if n > 1]
assert types[-1]["title"] == "GameHighScore"
print("methods=185; params=932 (177 tables, 8 empty); types=400; field_tables=365; fields=1888; updates=28")
```

**ما قورن آلياً:** headings، تكرار الأسماء، headers الجداول، عدد صفوف المعاملات والحقول، وعدد حقول Update. **ما راجعته يدوياً:** أقسام التصنيف، آخر صف `GameHighScore`، Update fields، ربط dispatcher في Titan، wrappers المحدودة، `InputFile`/multipart، والموديلات المحلية. لم أراجع يدوياً دلالة كل method/type على حدة، ولم أشغّل كل API method عملياً؛ لا اتصال حي ولا credentials.

السكربت يعيد جلب صفحة المرجع ويعيد إنتاج الأعداد وفحوص الاكتمال/التكرار؛ لا يعيد توليد ملف Markdown كاملاً ولا يثبت صحة معنى كل صف. تعيين `Titan` في المصفوفة هو مقارنة ساكنة مع الملفات التالية:

## ما يدعمه Titan فعلياً

- `Telegram.request(method, data)` يقبل اسماً عاماً ويرسل body بصيغة JSON إلى Bot API. بذلك يوجد مسار خام يمكن للمطور استدعاؤه؛ لا يوجد schema type checker أو Action registry أو metadata صلاحيات لكل method.
- توجد 26 convenience/adaptor wrappers لطرق Bot API: `getMe`, `getUpdates`, `sendMessage`, `editMessageText`, `deleteMessage`, `banChatMember`, `getChatMember`, `leaveChat`, `sendChatAction`, `answerCallbackQuery`, `sendPhoto`, `sendVideo`, `sendDocument`, `sendAudio`, `sendSticker`, `sendAnimation`, `forwardMessage`, `copyMessage`, `pinChatMessage`, `unpinChatMessage`, `unpinAllChatMessages`, `getChat`, `getChatMemberCount`, `setMyCommands`, `deleteMyCommands`, `getMyCommands`. كلها subset wrappers. `sendRichMessage` helper خاصة بـ Titan تُحوّل الرسالة إلى API method رسمي، وليست method ضمن Bot API. لا يعني ذلك تغطية سائر المعاملات/الحقول.
- generic transport يرسل JSON ولا يدعم رفع bytes عبر `multipart/form-data` لـ `InputFile`. يمكن لحقول وسائط تعتمد على file_id أو URL أن تكون قابلة للإرسال عند قبولها من Telegram، لكن رفع ملف محلي ليس منفذاً بهذا transport.
- النماذج typed الجزئية في Titan: `Update`, `Message`, `Chat`, `Sender` (subset من User)، ومساعد محلي اسمه `ChatPermissions` لا يطابق schema الرسمية بالكامل. لا توجد نماذج لكل 400 نوعاً أو validation لكل حقل. التفاصيل أدناه.
- توجد اختبارات واسعة للإطار (`992 passed`) واختبارات محددة للـ transport/adapter/update؛ لا يوجد اختبار endpoint-by-endpoint أو اتصال حقيقي بحساب Telegram.
- `setMyCommands` و`deleteMyCommands` متاحتان كـ wrapper في Titan فقط؛ لم يظهر استدعاؤهما من Hozan startup. لم يجر تغيير قائمة أوامر BotFather.

## دلالات وحدود التغطية

1. **الطريقة الخام ليست دعماً منتجياً كاملاً:** لا توجد في SourceFarm طبقة Actions قابلة للعرض، ولا أنواع معاملات، ولا تحقق للحقول، ولا metadata لصلاحيات البوت أو سياق المحادثة. استدعاء endpoint عبر اسم نصي لا يحقق مطلب Builder.
2. **Update support أضيق من Bot API:** dispatch يمرر message/channel_post/callback_query، ويستخدم offset؛ بقية التحديثات لا تملك handlers. الـ raw dictionary يبقى متاحاً في Titan لبعض حالات الاستخدام اليدوي، لكنه لا ينشئ Trigger تلقائياً.
3. **الموديلات مبسطة:** نموذج Titan `Message` لا يمثل كائن Telegram `Message` الكامل؛ و`Sender` ليس User model كاملاً. كما أن helper المسماة `ChatPermissions` لا تطابق نوع Telegram الرسمي، بل تمثل 11 حقل admin مستخرجة من عضو chat. ما عدا ذلك raw JSON.
4. **ملفات الوسائط:** الرفع المحلي يتطلب multipart؛ JSON transport الحالي لا ينفذه. راجع `InputFile` ووسائط API بالجدول أعلاه.
5. **الاختبارات لا تختبر Bot API live:** نتائج الاختبارات المحلية تثبت behavior داخلياً مع mocks/fixtures، لا صحة API credentials أو حقوق إدارة في مجموعات/قنوات حقيقية.
6. **الأوامر:** BotFather القائمة حسب إفادة المستخدم مسجلة مسبقاً؛ لا يوجد ما يبرر إعادة ضبطها هنا. Titan wrappers لإدارة القائمة موجودة، لكن Hozan لا يستدعيها.
